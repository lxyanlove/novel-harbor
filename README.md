# 书港 · Book Harbor

可部署到 Cloudflare Workers 的多书源小说搜索、抓取与 TXT / EPUB 导出网站。类似“阅读”的书源配置思路，独立实现，**不是阅读完整规则引擎的移植版**。

## 先部署

1. 把本目录的文件上传到一个 GitHub 仓库**根目录**，包括 `public/`、`src/`、`package.json`、`pnpm-lock.yaml`、`pnpm-workspace.yaml`、`wrangler.jsonc`；不要上传 `node_modules`、`.wrangler`、`dist` 或访问口令。
2. 打开 `https://deploy.workers.cloudflare.com/?url=https://github.com/你的账号/你的仓库`（替换仓库地址）。这是 Cloudflare 官方部署向导；首次需登录 Cloudflare 并授权 GitHub。公开仓库可用部署按钮。
3. 项目名称可保持 `novel-harbor`，无需数据库、R2、KV、付费 API 或构建命令；部署命令为 `npm run deploy`（实际调用 Wrangler）。仓库声明的 pnpm 版本与锁文件用于安装依赖。
4. 部署完成后打开 Cloudflare 返回的 `workers.dev` 地址。
5. 添加自己的书源前，先决定代理的放行方式：
   - **设了 `ACCESS_TOKEN`（推荐）**：代理自动放开到任意公网域名，以后加书源不用再改任何配置——因为此时只有带口令的请求能用这个代理。IP 字面量、localhost、内网域名无论何时都会被拒绝。
   - **不设口令**：走白名单。把书源涉及的域名逐个加进 `wrangler.jsonc` 的 `vars.ALLOWED_HOSTS`（逗号分隔、不含 `https://`、**精确匹配**——`www.a.com` 和 `a.com` 要各写一条），然后重新部署。也可在 Cloudflare Worker 设置里改变量以免重新部署，但下次从 Git 部署会把配置文件的值覆盖回去，两边要一致。
   - 两者兼得（设了口令但仍锁白名单）：再加一个 `STRICT_ALLOWED_HOSTS=1`。

如果使用 Cloudflare 控制台连接已有仓库：选择 **Workers** 项目，仓库根目录，构建命令留空，部署命令 `npm run deploy`。不需要 GitHub Actions 密钥。后续推送可通过 Workers Builds 自动更新。

网站的「设置与部署」也有仓库地址输入框，可生成上述官方入口。没有填写真实仓库地址前，不伪造可用部署按钮。

可选：在 Cloudflare 的变量/机密中设置 `ACCESS_TOKEN` 为长随机口令，再在网站「设置」中输入该口令。口令只保存在当前浏览器标签页会话中，不进入书源导出文件。**设了口令同时会放开域名白名单**，所以公开站点务必用足够长的随机值，否则这个 Worker 就等于一个公开代理。当前没有服务端用户账户或按用户计费/限流。

## 已实现

- 多书源并行搜索；保留同一本书的不同来源，支持按源筛选和搜索下一页。搜索结果会带出来源标注的「最新章节」，并按书名把同名书归到一组。
- 下载前先体检：只抽样 8 章（含首章和末章），给出抓取完整性与文本质量两个分数，几分钟内判断这个来源值不值得整本下载。
- 体检提示同书其他来源的章节数与末章，章数明显偏少的那个多半是残本。
- 文本质量检查正文里的站点广告与水印、乱码与错误转码、重复段落、疑似截断、过短章节和排版失范；「作者求票」「未完待续」这类连载常见痕迹只做低权重提示。
- JSON 文件/粘贴导入、导出、启停、查看/修改书源；单源错误不会中断其他搜索。导入时区分「错误」与「提示」：缺必需规则或依赖脚本的才跳过，只多带了用不上的可选子规则仍然导入。
- 一键导入随项目附带的 931 条公开合集；导入报告会汇总跳过原因，并把当前启用书源用到的域名整理成一行 `ALLOWED_HOSTS` 供直接粘贴，另有「复制域名白名单」按钮。
- 书源兼容「阅读」默认规则的纯 HTTP 子集：`&&`/`||` 组合、`##` 正则替换、`$..` 递归 JSONPath、`.N`/`!N`/`.-1` 索引与 `.A:B` 取值段、`{{(page-1)*10}}` 模板运算、书源 `header` 里的 UA/Referer。用一份 931 条的公开合集实测，可导入 244 条。
- 一个书源都没启用时，搜索改用搜索引擎找候选站点；每条候选可探测搜索页、一键生成书源模板。
- 内置中文维基文库、英文 Wikisource 和 Gutenberg 适配器。英文文库默认关闭。内置仅作入口，网站范围通过自定义书源扩展，并非全网搜索引擎。
- 搜索 → 详情 → 目录 → 正文的规则抓取；GET / 表单 POST；目录分页和正文分页。
- 默认 3 路章节并发，可调 1–6；本标签页同域名发起请求至少相隔 350 毫秒；可重试错误最多重试 2 次。限速只约束当前页面，不是全站服务端限流。
- 暂停、刷新后续传、只重试失败章节，正文与任务保存在本浏览器 IndexedDB。**关闭页面会停止抓取，重新打开后需手动续传**；没有云端后台任务。
- TXT 为 UTF-8（含 BOM）；EPUB 为实际 EPUB 3 ZIP，包含目录、章节、作者、来源与质量报告。纯文本导出，不保留原站图片、脚注跳转和复杂排版。
- 有异常默认阻止导出；手动允许后保留缺失章节占位和质量报告，文件名标为「待核验」。
- 手机/电脑布局，无第三方 CDN、远程字体、追踪或广告。

## 添加书源

1. 打开「书源管理」，点「导入内置合集」直接载入随项目附带的 931 条公开合集（无需自己找文件），或导入自己的阅读风格 JSON，或使用 `examples/source-template.json` 按真实站点修改。
   单个文件最大 10 MB、1500 个书源；大型合集会逐项检查，只导入当前引擎支持的来源，并汇总其余项目的跳过原因。
2. 查看兼容性报告。被拒绝的源不会自动降级为一个看似成功的空书源。
3. 让服务端允许这个来源的域名：设了 `ACCESS_TOKEN` 的话已经自动放开，不用做任何事；没设口令则把源域名加入服务端 `ALLOWED_HOSTS`（仅域名，逗号分隔，不含 `https://`；精确匹配，`www` 要单独列）。这是站点管理员的一次性配置，防止这个 Worker 被当成公开代理。**导入后报告里会直接给出这一行**，也可以点「复制域名白名单」把当前启用书源的全部域名复制走。这一步给出的域名列表**已经并上了服务端当前允许的域名**（内置书源和搜索引擎），可以整行替换 `ALLOWED_HOSTS`；如果你只把书源的域名填进去、丢掉内置那几条，维基文库、Gutenberg 和「用搜索引擎找站点」都会失效。整份 931 条合集导入后这一行约 3.3 KB，Cloudflare 文档说单个环境变量上限 5 KB，很接近上限——所以更省事的做法还是设 `ACCESS_TOKEN`。
4. 在首页填入该站确实存在的书名，点击书源管理里的「测试」。这个测试只验证搜索；还需要实际打开目录、抽查正文。
5. 如需修改已导入规则，点击「查看规则」、编辑 JSON 后再次导入；相同 `bookSourceUrl` 会替换旧规则。

模板域名 `example.com` 是占位符，**不是可用小说站**。网站改版、地区网络、robots/访问策略和反爬会影响书源。仅使用允许访问及下载的来源，不提供登录绕过、验证码绕过、DRM 或付费内容解锁。

### 规则兼容范围

实现的是「阅读」默认规则里纯 HTTP 能复刻的那部分：

| 能力 | 当前支持 |
| --- | --- |
| 搜索模板 | `{{key}}`（UTF-8 URL 编码）、`{{page}}`、`{{baseUrl}}`，以及四则运算如 `{{(page-1)*10}}` |
| 请求选项 | URL 后接 `,{"method":"POST","body":"q={{key}}","charset":"gbk"}`；仅 method/body/charset。老书源的写法（单引号、键名不加引号、换行）会先补引号再按 JSON 解析，不执行任何脚本 |
| HTML 选择器 | 标准浏览器 CSS，`@css:` 前缀；`id.x` / `class.x` / `tag.x` 前缀；每一步末尾可带 `.N`（支持 `.-1`）、`:eq(N)`、老书源的 `!N`，以及 `.A:B` 取一段 |
| 末尾属性 | `@text`、`@html`（两者都提取纯文本）、`@href`、`@src`、`@content`、`@value`、`@data-*`；也可写成裸的 `text` / `href`。属性名走白名单，所以 `id.at@a` 里的 `a` 是选择器而不是属性 |
| 组合规则 | `&&` 按顺序拼接（`$..cate_name&&$..status_str`），`||` 取第一个非空；用在列表规则上时两者都取并集 |
| 正则替换 | `规则##正则` 删除匹配，`规则##正则##替换` 替换（替换串支持 `$1`） |
| XPath | `//div[@id='content']`、`.//a/@href` 等节点集 XPath；字符串计算函数不支持 |
| JSONPath | `$.data.books[*]`、`$.data[0].title`、`$..key` 递归查找、`[-1]`；不支持过滤表达式 |
| 请求头 | 书源 `header` 里的 User-Agent、Referer、Accept、Content-Type、`X-*` 会转发 |
| 目录 | `chapterList` / `chapterName` / `chapterUrl` / `nextTocUrl` |
| 正文 | `content` / `nextContentUrl`；分页选择器必须指向本章下一页，不能指向下一章 |
| 字符编码 | 默认按响应头或 UTF-8；可显式设置 utf-8 / gbk / gb18030 / big5，并接受 `gb2312`、`ansi` 这类常见别名（都按 gbk 处理） |

不支持的：任意 JavaScript（`@js:`、`<js>`）、Java 桥接、WebView、`@get:`/`@put:` 变量、登录源、Cookie 与 Authorization（凭据头一律不转发）、图片/音频源（`bookSourceType` 非 0）、`init` 预处理。这些在导入时会明确说明原因。

缺少必需规则、或确实依赖上述脚本能力的书源会被跳过；只是多带了 `updateTime`、`isVip` 这类用不上的可选子规则时只给提示、仍然导入——因为一个用不上的字段就把整条书源作废，会白丢大量本来能用的源。用你那份 931 条合集实测：**可导入 244 条**（其中 177 条带提示），其余 687 条里约 600 条依赖脚本或登录，属于纯 HTTP 引擎无法复刻的部分。**必需的**规则（搜索地址、书名、链接、目录、正文）里含算不出来的模板时按错误处理——例如 `{{cookie.removeCookie(...)}}`，这种源导入成功也永远搜不到，不如在导入时就说明白。`.A:B` 的取值段语义在公开资料里没有明确定义，实测只出现在 `kind` 这类展示字段上，因此按「取 A 到 B 一段」实现，写反了也取同一段。

导入成功仍然只是语法兼容。站点改版、Cloudflare 出口被拒、来源授权状态，都要实际测试过才算数。

**能导入 ≠ 能搜到。** 书源合集是公开流传的，里面大量条目早已失效。用合集里的 10 条做端到端实测（本机网络，不是 Cloudflare 出口）：6 条通过导入，实际搜索时 0 条返回结果——3 条域名在本机直接解析不了，2 条站点已改版（接口不再接受原来的参数），1 条搜索接口返回「请输入搜索关键字」而书源里写的参数名已经对不上。这些都不是引擎报错，而是站点本身的状态。所以导入后请用「用当前关键词测试书源」逐个筛，再逐个体检，不要指望一次导入就有几百个可用来源。

展示字段（作者、简介、分类、字数、最新章节）的选择器写错时只跳过该字段，不会让整条书源的搜索失败；书名和链接这类必需字段出错仍然会明确报出来。

## 没加书源时：用搜索引擎找站点

一个书源都没启用时，搜索会自动改用搜索引擎；首页也有「找不到？找站点 ↗」入口。

- 默认用**必应（中国）**。实测从数据中心 IP 出发，必应、百度、搜狗都还能返回结果，而 DuckDuckGo、Mojeek、Brave、Startpage 一律直接 403——Cloudflare 的出口 IP 同样属于这类网段，所以默认选必应。可在「设置」里切换。
- 结果里只保留疑似小说站的域名，百科、社区、影视、电商会被过滤并计数。
- 每条候选可以「探测搜索页」：按 7 种常见写法（含笔趣阁系常用的 `/modules/article/search.php?searchkey=`）各搜一次这本书，命中书名且链接足够多就报告哪个地址可用。**探测前要先让该域名可用**：设了 `ACCESS_TOKEN` 就不用管，否则要把它加进 `ALLOWED_HOSTS`；两种情况界面都会明确说明，而不是含糊地报失败。
- 「建书源」把探测到的搜索地址填进模板。模板里的选择器只是常见写法的猜测，必须打开网站按实际页面结构改过才能用。

这一步只解决「去哪儿找」，不解决「怎么抓」——真正的抓取仍然要有一条能用的书源规则。

大型阅读合集通常混有 API、登录、验证码、JS 解密、漫画和有声规则。导入器会读取整份合集，但只保留能由当前安全子集解释的书源；“导入成功”仍只是语法兼容，站点改版、跳转、Cloudflare 出口网络和授权状态都要再测试。

## 下载前体检：完整性与文本质量

体检只抽样 8 章（首章、末章，其余在全书均匀铺开），给出两个互相独立的分数。抽查位置刻意包含首末两章——目录错位和正文截断最容易在这两处暴露。

成功抓完目录里的 100 章，不代表原著只有 100 章。目录规则漏选、网站本身缺失、不同版本分卷、连载未完结，都不能仅凭网络请求成功判断。

**抓取完整性**：目录有多少章、成功抓了多少章、编号是否连续、目录范围是否确认。失败按比例扣分；只有「整页拦截」「目录为空」「预期章数不符」「≥5% 章节没抓到」才把总分压到 45——零星一两章失败不会否定整本书。几个来源都有这本书时，比较各自的章节数与末章，章数明显偏少的多半是残本。

**文本质量**：按症状扣分，每类有单独上限。

| 症状 | 权重 | 检出内容 |
| --- | --- | --- |
| 站点广告与水印 | 32 | 「一秒记住」「笔趣阁」「无弹窗」、残留网址、拆字域名 |
| 乱码与错误转码 | 40 | 替换字符、`锟斤拷`、成片方框 |
| 重复段落 | 20 | 同一章内出现完全相同的段落 |
| 疑似截断 | 20 | 章节结尾不是完整句子 |
| 过短章节 | 15 | 明显短于本书其他章节 |
| 标记与隐形字符残留 | 12 | HTML 标签、未解码实体、零宽字符 |
| 排版失范 | 12 | 整章几乎不换行、中文里混用半角标点 |
| 作者感言与更新说明 | 10 | 求票、「未完待续」——连载原文常带，只做提示 |

短章以**本书自身的中位数**为基准，所以诗集、散文集整本都短也不会被误判。单项症状拉满时（例如每一章都以非句末标点结尾），总分也会被相应压低，不会因为其他项正常而蒙混过关。

**分数不等于校对认证。** 书名里写「精校版」只作为来源自述显示，不会加分。分数是基于可观测症状的启发式评分，用途是在多个来源之间排序取舍：

- 「抓取不完整」：存在抓取失败、未抓取或预期章数不符。
- 「文本质量存疑」：正文出现大面积乱码等硬伤。
- 「需要人工核验」：疑似缺章、重复、截断、短章、编码错误，或目录覆盖无法确认。
- 「未发现明显抓取异常」：只是当前自动检查未检出问题，不等于完整、完结或已精校。

体检不能替代人工抽查：分数再高也可能漏掉错别字、错行或作者本人的笔误。错别字级别的「校对」无法从文本自动确认，工具只报告它真正看得见的症状。

维基文库目前自动收集以 `书名/` 开头的链接；其他命名形式、分卷目录或复杂跨页面版本不能保证覆盖。该适配器一律标记目录覆盖待核验；遇到进一步子目录会报错而非把目录当正文。Gutenberg 读取其文本全文，保留原文件许可说明，但没有独立章数可供比对。

## 免费部署的边界

界面使用 Workers Static Assets，正文解析、质量检查和 EPUB 生成在用户浏览器；Worker 只处理受域名限制的抓取与短期缓存。没有必须付费的资源。

截至 2026-10-09 查阅的 Cloudflare 文档：免费 Workers 每日 100,000 次请求；静态资源请求免费且不限量。抓取 API 会占用 Worker 配额，重试/章节分页也会增加请求；免费 CPU、内存、子请求限制仍适用。8 MB 大页面不保证符合免费 CPU 预算，应优先使用逐章小页面。超限会失败，不能承诺任意访问量一直免费。Cloudflare 的 IP 也可能被目标网站拒绝。

当前保护上限：单页 8 MB、单次请求 20 秒、目录 50 页 / 5000 章、单章正文 20 页、单任务 2000 万字符。超过目录/正文分页限制会报错停止，不会静默把截断内容当成完成。原文未完成、反爬返回 200 的伪正文、乱码等仍需人工抽查。

## 本地运行

安装 Node.js 22 或更新版本，然后：

```sh
npm install
npm run dev
```

或使用仓库锁定的 pnpm：

```sh
corepack enable
pnpm install
pnpm dev
```

只想预览、不安装依赖：`node scripts/preview.mjs`。此服务使用 Node 模拟接口，不提供 Cloudflare Cache，也不会读取 `.dev.vars`；用环境变量设置 ALLOWED_HOSTS / ACCESS_TOKEN。真正 Worker 本地测试使用 `npm run dev`。

`node_modules` 里的 `workerd` 是**按安装平台**下载的原生二进制：在 Windows 装的、拿到 WSL 里跑会报「workerd 装在另一个平台」。换平台时删掉 `node_modules` 重新 `npm install` 即可。只用 `scripts/preview.mjs` 预览则不需要它。

`.dev.vars.example` 可复制成 `.dev.vars`，填入本地访问口令；不要提交真实口令。不要双击 HTML，接口需要 HTTP 服务。

## 验证与项目结构

```sh
npm test              # 25 项核心测试：抓取限制、规则导入、规则语法、体检评分、导出结构
npm run check         # 各模块语法检查
npx wrangler deploy --dry-run
```

`scripts/ui-smoke.mjs` 为可选浏览器集成测试，需可导入的 Playwright 和 Chrome；通过 `PLAYWRIGHT_MODULE` 指向已安装的 Playwright `index.mjs`。如果本机装不上 Chromium 的系统依赖（缺 `libnspr4` 之类又没有 sudo），可以设 `CDP_ENDPOINT` 复用一个已经开着的浏览器：

```sh
# Windows 侧（WSL 镜像网络下 127.0.0.1 双向互通）
chrome.exe --headless=new --remote-debugging-port=9222 --user-data-dir=%TEMP%\chromeprof
# WSL 侧
PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs CDP_ENDPOINT=http://127.0.0.1:9222 node scripts/ui-smoke.mjs
```

测试使用受控模拟书源，覆盖导入、搜索、两种分页、下载前体检、同书对比、抓取失败、刷新后续传、导出阻止、页面内 EPUB 字节校验、TXT/EPUB 下载及移动布局。远程 CDP 模式下浏览器会把文件写在自己的磁盘上，所以只校验下载文件名，EPUB 结构改由页面内生成的字节直接校验。模拟测试不代表真实网站已经验证。

`scripts/live-smoke.mjs` 实测内置公开 API。交付时本机网络对 Gutenberg / 中文维基文库超时，未确认真实源端到端可用；知乎参考页面也未能读取，因此未伪造知乎站点名单或导入未核验的书源合集。

- `public/`：界面、规则引擎、存储、质量检查和格式导出。
- `src/worker.js`：有大小/时间/域名限制的抓取接口；每次重定向重新验证域名。
- `wrangler.jsonc`：部署配置和允许访问的域名。
- `examples/`：书源模板。
- `public/examples/bookSource.json`：随站点附带的 931 条公开合集，「导入内置合集」按钮读的就是它（实测可导入 244 条）。
- `tests/`、`scripts/`：核心测试与本地预览、集成验证。
